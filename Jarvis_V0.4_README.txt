Jarvis V0.4
A local, voice-first coding and research assistant built around Ollama, with a holographic control-center UI, filesystem tools, a controlled Python runner, Tavily web search, and a permanent log book.

Project layout
Jarvis/
├── app.py                   <- main entry point: starts the server and opens the Jarvis window
├── server.py                <- local backend: bridges the UI to the agent over a WebSocket
├── Agent.py                 <- system prompt, Ollama tool schemas, tool-calling loop (also runs standalone in the terminal)
├── requirements.txt         <- every Python package Jarvis needs
├── .env                     <- your TAVILY_API_KEY (never committed)
├── .env.example             <- safe template for .env
├── ui/
│   └── index.html           <- the control center, log book, and permission popup
├── logs/
│   └── logbook.jsonl        <- created automatically, one line per tool call (never committed)
├── Tools/
│   ├── __init__.py          <- re-exports the tool functions
│   ├── filesystem.py        <- sandbox path + list/read/create/edit/delete + confirmation hook
│   ├── python_runner.py     <- run_python for Python files in Test/
│   ├── web_search.py        <- web_search using Tavily
│   ├── speech_to_text.py    <- listen, microphone -> text via Google Web Speech
│   └── text_to_speech.py    <- speak, text -> audio via pyttsx3
└── Test/
    └── hello.py             <- sample file in the sandbox
Jarvis should be run from inside the Jarvis/ directory so the Tools package imports correctly.

What Jarvis can do
Run as a desktop app with a live control center: model and iteration, tool-usage stats, a voice core that reacts to what Jarvis is doing, and quick commands.

Listen to your voice and speak its replies. Click the core once and Jarvis keeps listening until you say "exit", "quit", or "bye", or press STOP.

List, read, and create files inside the Test/ sandbox.

Edit and delete files inside the sandbox, but only after you approve a popup that names the file. Edits show a before/after diff.

Run existing .py files inside the sandbox with run_python.

Search the internet with web_search through Tavily.

Record every tool call in the Log Book, with filters and search. The log is saved to disk, so it survives restarts.

Requirements
Python 3.11 or newer

Ollama, with the model qwen2.5-coder:7b

A Tavily API key for web search

portaudio (macOS system library, needed for the microphone)

An internet connection (speech recognition uses Google Web Speech, and web_search uses Tavily)

A working microphone and speakers

The Python packages are all listed in requirements.txt:

Setup
1. Start Ollama
ollama serve
Make sure the model is installed:

ollama pull qwen2.5-coder:7b

2. Install the system dependency for microphone input (macOS)
brew install portaudio
Do this before step 3, because pyaudio will not build without it.

3. Install the Python dependencies
From the Jarvis directory:

python -m pip install -r requirements.txt

If you add a new package later, add it to requirements.txt too.

4. Add your Tavily API key
Create a file named .env in the Jarvis directory containing one line:

TAVILY_API_KEY=your_real_key_here

Jarvis loads it automatically at startup, so there is no need to export it in the terminal.
.env must be listed in .gitignore. Never put the key in any file that will be committed to GitHub. If a key was ever committed, treat it as burned and rotate it in the Tavily dashboard.

5. Keep private files out of Git
Make sure .gitignore contains:

.env
logs/

The log book saves what you say to Jarvis, so logs/ should never be uploaded.

Run Jarvis
From inside ~/Jarvis/:

python app.py

A Jarvis window opens. If the native window can't start on your Python version, Jarvis opens the same page in your browser instead (http://127.0.0.1:8765).

You can still run the old terminal version with python Agent.py. In that mode edit and delete confirmations fall back to a y/N prompt in the terminal.

Using Jarvis
Click the core to start listening. It cycles through listening, processing, speaking, and back to listening.

Say "bye" (or press STOP) to end the conversation.

Approve or deny any edit/delete popup with YES or NO. Esc counts as NO.

Open the LOG BOOK tab to see everything Jarvis has done. Filter by FILES, RUN, WEB, or VOICE, or type in the search box.

SHUT DOWN shows the offline screen. BOOT JARVIS brings it back, and QUIT APP closes the whole app.

Test it
Say: "Create a file called hello2.py that prints Hello from Jarvis"
Then: "List the files in the sandbox."
Then: "Edit hello2.py so it prints a second line." You should see the permission popup with a diff.
Then: "Run hello.py." Jarvis should call run_python and report the result.
Then: "Search the web for the official Python asyncio documentation."
Then check the LOG BOOK tab: every step above should be listed.

No microphone handy? Open http://127.0.0.1:8765/#dev in your browser and a text box appears so you can type commands instead of speaking.

Security model
Jarvis does not provide arbitrary shell execution.

Filesystem tools are restricted to the Test/ sandbox. Requests that escape the sandbox are rejected by the filesystem safety checks.

Edits and deletes both require your approval. (In V0.3 only deletes did.) If you close the popup, press Esc, press STOP, or do nothing for 2 minutes, the answer is NO and nothing is changed.

The backend only listens on 127.0.0.1, so other computers cannot reach it. It also rejects WebSocket connections from any page that is not Jarvis itself, so other websites open in your browser cannot talk to it.

run_python only accepts an existing .py file inside Test/. It is a controlled Jarvis tool, but it is not a security sandbox for untrusted Python code: once a script starts, Python itself has normal process privileges.

Web search is separate from filesystem access. web_search can search the public internet through Tavily, but it does not give the model arbitrary browser or computer control.

Voice input only starts when you click the core. Jarvis does not listen in the background, and the microphone stops when you press STOP.

On macOS you may be asked to let Terminal or VS Code use the microphone the first time. Click Allow.

Tool architecture
app.py starts the server in the background and opens the Jarvis window.

server.py wraps every tool in Agent.FUNCTIONS so each call is logged and sent to the UI, registers the confirmation handler, runs the listen/think/speak loop, and pushes live state to the UI over a WebSocket. Agent.py's own logic is not modified by it.

Agent.py contains the system prompt, Ollama tool schemas, function mapping, and tool-calling loop.

Tools/filesystem.py contains filesystem operations, sandbox enforcement, and set_confirm_handler(), the hook the UI uses to show the Yes/No popup. With no handler registered it falls back to input().

Tools/python_runner.py contains the controlled Python execution tool.

Tools/web_search.py contains the Tavily integration.

Tools/speech_to_text.py and Tools/text_to_speech.py contain the microphone and voice-output helpers.

ui/index.html is a single page (Tailwind, Lucide icons, Orbitron/JetBrains Mono fonts) with the control center, log book, and permission popup.

What's new in V0.4
Added a full desktop UI: a holographic control center with a live voice core, status rings, tool-usage donut, and quick commands.

Replaced typing "voice" with a clickable core. One click starts a continuous listen/think/speak loop.

Added a permission popup for edits and deletes. Edits now require approval too, and they show a diff.

Added the Log Book: every tool call is recorded with a timestamp, category, detail, and result, and saved to logs/logbook.jsonl.

Added server.py and app.py so the UI and the existing agent work together without rewriting Agent.py.

Added requirements.txt so all dependencies install with one command.

A denied edit now ends the turn, the same way a denied delete does, so the model does not keep asking.

Known limitations
The CALL button is a placeholder and does nothing yet.

pywebview may not install on very new Python versions. Jarvis falls back to your browser if the native window can't open.

Speech recognition and Tavily both need an internet connection.

The small local model sometimes retries a failing tool. The tool-call limit in Agent.py stops it from looping forever.

Important development notes
Keep API keys out of source code and out of Git history.

Before committing changes:

git status
git add .
git commit -m "Describe the change"
git push
Check that git status does not list .env or logs/ before you commit.

For major milestones, create a Git tag so older versions remain easy to identify:

git tag -a v0.4 -m "Jarvis V0.4 - holographic UI, permission popups, log book"
git push origin v0.4
